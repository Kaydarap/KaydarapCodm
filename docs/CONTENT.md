# راهنمای مدیریت محتوا

## ورود به پنل

آدرس: **https://www.kaydarap.com/admin/**

ورود با حساب GitHub انجام می‌شود. فقط حساب‌هایی که روی ریپازیتوری دسترسی نوشتن (Write) دارند می‌توانند تغییرات را ذخیره کنند. هیچ رمز ثابتی در سایت وجود ندارد.

دو روش ورود:

1. **Sign in with Token** (بدون نیاز به سرویس اضافه):
   در GitHub بروید به *Settings → Developer settings → Personal access tokens → Fine-grained tokens*، یک توکن فقط برای ریپازیتوری `Kaydarap/KaydarapCodm` با دسترسی **Contents: Read and write** بسازید و در صفحه ورود پنل وارد کنید.
   توکن فقط در مرورگر خودتان ذخیره می‌شود. آن را برای هیچ‌کس (از جمله چت) نفرستید.
2. **Sign in with GitHub** (اختیاری): نیازمند راه‌اندازی [sveltia-cms-auth](https://github.com/sveltia/sveltia-cms-auth) روی Cloudflare Workers (رایگان) و قرار دادن آدرس آن در `public/admin/config.yml` → `backend.base_url`. مقادیر محرمانه فقط در تنظیمات همان Worker قرار می‌گیرند (نمونه در `.env.example`).


## چه چیزهایی قابل ویرایش است

| بخش پنل | فایل | محتوا |
|---|---|---|
| Rules → Android / iOS | `src/data/rules-*.json` | عنوان، متن پایانی، نسخه، تاریخ ویرایش، مراحل (متن هر زبان جدا)، برچسب‌ها، دکمه فروشگاه |
| Open rooms | `src/data/rooms.json` | روم‌ها (زمان، ظرفیت، وضعیت ثبت‌نام، لینک) و اطلاعیه‌ها |
| FAQ | `src/data/faq.json` | پرسش و پاسخ در سه زبان |
| Home page | `src/data/home.json` | متن اصلی صفحه خانه، تصویر بنر، نوار اطلاعیه |
| — (ویرایش مستقیم در GitHub) | `src/data/champion.json` | بخش‌های Champion Rules (تنظیمات، مپ‌ها، وتو، اسلحه‌ها، پرک‌ها، اسکوراستریک‌ها و…) در سه زبان؛ بعد از هر تغییر رسمی، `sourceUpdatedAt` و `checkedAt` را هم به‌روز کنید |
| Site settings & links | `src/data/settings.json` | لینک Champion Rules، لینک Integrity Check، لینک مایکت، لینک تماس |

هر ذخیره در پنل = یک commit روی شاخه `main` → سایت حدود ۱ تا ۲ دقیقه بعد خودکار به‌روز می‌شود.

## قالب متن قوانین

- `**متن**` → برجسته (مثلاً نام تنظیمات: `**Developer Mode**`)
- `` `متن` `` → کلمه قابل کپی با دکمه کپی (مثلاً `` `cod` ``)

## ترجمه‌ها

هر زبان یک بخش جداگانه است؛ ویرایش فارسی هیچ تغییری در انگلیسی یا عربی ایجاد نمی‌کند.

وقتی معنای یک متن را در یک زبان عوض کردید، در **دو زبان دیگر** تیک **Translation needs update** را بزنید. این موارد:
- در خروجی `npm run check` و گزارش هر انتشار در GitHub Actions به‌صورت هشدار فهرست می‌شوند؛
- انتشار را متوقف نمی‌کنند.

اگر متن یک زبان خالی بماند، انتشار متوقف می‌شود تا صفحه ناقص منتشر نشود.

## نسخه و تاریخ قوانین

بعد از هر تغییر واقعی در قوانین، **Rules version** (مثلاً ۱.۰ → ۱.۱) و **Last updated** را به‌روز کنید. این دو مقدار بالای صفحه قوانین نمایش داده می‌شوند.

## شناسه مراحل (Step ID)

پیشرفت چک‌لیست کاربران بر اساس شناسه مرحله ذخیره می‌شود. شناسه مراحل موجود را تغییر ندهید؛ برای مرحله جدید شناسه جدید بسازید.

## اوپن‌ روم

فقط اطلاعات واقعی وارد کنید. ظرفیت و تعداد ثبت‌نام اختیاری‌اند؛ اگر خالی بمانند اصلاً نمایش داده نمی‌شوند. زمان شروع برای هر بازدیدکننده به منطقه زمانی خودش تبدیل می‌شود و شمارش معکوس خودکار است.

## ویرایش بدون پنل

می‌توانید فایل‌های `src/data/*.json` را مستقیم در GitHub ویرایش کنید یا Pull Request بسازید؛ PR به‌طور خودکار build و بررسی می‌شود.
